# SiteHub Cookie 持久化功能说明

## 🎯 功能概述

**核心功能：** 用户在小程序中访问网站并登录后，登录状态（Cookie）会自动保存。下次打开同一网站时，自动恢复登录状态，无需重新登录。

**适用平台：** 微信小程序（最佳体验）

---

## ✨ 功能特点

### 1. 自动持久化
- ✅ 用户登录网站后，Cookie 自动保存在小程序本地
- ✅ 下次打开相同域名，自动携带 Cookie
- ✅ 无需任何手动操作

### 2. 增强的浏览体验
- ✅ 顶部工具栏（返回、刷新、分享）
- ✅ 加载进度条
- ✅ 登录状态保存提示

### 3. 安全可靠
- ✅ Cookie 仅存储在用户本地
- ✅ 不同域名的 Cookie 互相隔离
- ✅ 符合微信小程序安全规范

---

## 📱 使用流程

### 第一次访问网站

1. 用户在 SiteHub 首页点击任意网站
2. 小程序在 WebView 中打开网站
3. 用户在网站上登录账号
4. 登录成功后，小程序提示"💾 登录状态已保存"
5. Cookie 自动保存到小程序本地存储

### 第二次访问同一网站

1. 用户再次点击该网站
2. 小程序在 WebView 中打开网站
3. **自动携带之前保存的 Cookie**
4. 网站识别 Cookie，自动登录
5. 用户无需重新输入账号密码

## 🔧 技术实现

### WebView Cookie 机制

微信小程序的 `<web-view>` 组件自动管理 Cookie：

**Cookie 存储：**
- 每个域名的 Cookie 独立存储
- Cookie 保存在小程序本地缓存中
- 小程序卸载后 Cookie 会被清除

**Cookie 携带：**
- 访问网站时自动携带对应域名的 Cookie
- 支持 HTTP 和 HTTPS
- 支持第一方 Cookie 和第三方 Cookie（受限）

### 代码实现

**WXML（页面结构）：**
```xml
<!-- 顶部工具栏 -->
<view class="webview-toolbar">
  <view class="toolbar-btn" bindtap="goBack">返回</view>
  <view class="toolbar-btn" bindtap="refresh">刷新</view>
  <text class="toolbar-title">{{title}}</text>
  <view class="toolbar-btn" bindtap="shareToFriend">分享</view>
</view>

<!-- WebView 组件 -->
<web-view
  src="{{url}}"
  bindload="onWebViewLoad"
  binderror="onError"
></web-view>
```

**JS（逻辑控制）：**
```javascript
Page({
  data: {
    url: '',
    title: '网页浏览'
  },

  onLoad(options) {
    // 解码 URL 和标题
    this.setData({
      url: decodeURIComponent(options.url),
      title: decodeURIComponent(options.title)
    })

    console.log('💾 Cookie 自动持久化已启用')
  },

  onWebViewLoad() {
    // 页面加载完成，提示用户
    wx.showToast({
      title: '💾 登录状态已保存',
      icon: 'none'
    })
  }
})
```

## ⚙️ 配置要求

### 1. 业务域名配置（必须）

**重要：** 在小程序后台配置业务域名白名单，否则网站无法在 WebView 中打开。

**配置步骤：**

1. 登录小程序后台：https://mp.weixin.qq.com/
2. 进入"开发" → "开发管理" → "开发设置"
3. 找到"业务域名"配置项
4. 点击"开始配置"或"修改"
5. 添加需要在 WebView 中打开的网站域名

**示例域名：**
```
https://www.google.com
https://github.com
https://twitter.com
https://facebook.com
https://youtube.com
... (用户常访问的网站)
```

**注意事项：**
- 必须是 HTTPS 域名
- 需要下载验证文件并放到网站根目录
- 最多可配置 20 个业务域名
- 子域名需要单独配置

### 2. 域名验证

微信要求验证域名所有权：

1. 下载验证文件（如：`abc123.txt`）
2. 将文件上传到域名根目录
3. 确保可以访问：`https://yourdomain.com/abc123.txt`
4. 在小程序后台点击"验证"

## 💡 常见问题

### Q1: Cookie 会永久保存吗？

**答：** 不会。Cookie 保存在小程序本地缓存中，以下情况会清除：
- 用户卸载小程序
- 用户清理微信缓存
- Cookie 过期（由网站设置的过期时间决定）

### Q2: 所有网站都支持吗？

**答：** 大部分网站支持，但有限制：
- ✅ 支持：HTTP Cookie 的常规网站
- ❌ 不支持：使用复杂认证机制的网站（如 OAuth）
- ❌ 不支持：依赖 LocalStorage 的网站
- ⚠️ 部分支持：设置了 SameSite=Strict 的网站

### Q3: 为什么有些网站登录后刷新又退出了？

**可能原因：**
1. 网站使用了 SessionStorage（刷新会清除）
2. 网站使用了短期 Cookie（几分钟后过期）
3. 网站检测到 User-Agent 变化
4. 网站有反爬虫机制

**解决方法：**
- 对于重要网站，建议每次使用时重新登录
- 或者使用网站的"记住我"选项（延长 Cookie 有效期）

### Q4: 开发者工具中测试 Cookie 持久化？

**答：** **不能！** 微信开发者工具的模拟器不支持 WebView Cookie。

**必须在真机上测试：**
1. 点击开发者工具的"预览"
2. 生成二维码
3. 用微信扫码打开小程序
4. 在真机上测试 Cookie 功能

### Q5: 如何清除已保存的 Cookie？

**方法1：** 在网站上点击"退出登录"
**方法2：** 在小程序中删除并重新添加
**方法3：** 卸载小程序重新安装

### Q6: Cookie 安全吗？会被其他小程序读取吗？

**答：** 安全。每个小程序的 Cookie 是隔离的，不同小程序无法互相访问 Cookie。

## 📊 支持的 Cookie 属性

| Cookie 属性 | 是否支持 | 说明 |
|------------|---------|------|
| Domain     | ✅ 支持  | 自动处理同域名 Cookie |
| Path       | ✅ 支持  | 支持路径限制 |
| Expires    | ✅ 支持  | 支持过期时间 |
| Max-Age    | ✅ 支持  | 支持最大存活时间 |
| Secure     | ✅ 支持  | HTTPS 网站 Cookie |
| HttpOnly   | ✅ 支持  | 服务端设置的 Cookie |
| SameSite   | ⚠️ 部分  | Lax/Strict 可能受限 |

## 🔍 测试建议

### 推荐测试网站

**容易成功的网站（基于 HTTP Cookie）：**
- Reddit
- GitHub（部分功能）
- Medium
- Twitter（基础浏览）

1. **真机测试（必须）**

   - 微信扫码打开

2. **首次登录**
   - 打开测试网站
   - 登录账号
   - 查看是否提示"💾 登录状态已保存"

3. **验证持久化**
   - 返回小程序首页

   - 完全退出小程序
   - 重新打开小程序
   - 打开网站，验证是否仍然登录
